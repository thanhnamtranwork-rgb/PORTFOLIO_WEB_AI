01 / OVERVIEW

What does MoteLona do?

MoteLona is a bilingual assistant for this Portfolio, not a general-purpose chatbot. It can answer from public database records, the current page, the built-in glossary and approved project files. Supported FAQs run locally before hosted generation. A scope guard keeps ordinary model requests on topic; Web search is a separate, visitor-controlled path for public sources.

A

Find information

Ask about the profile, education, skills and projects using content actually supplied by the website and database.

B

Get a quick local answer

Common questions about the Portfolio, MoteLona, chat privacy and free-provider delays are answered by local rules and evidence before any model API is considered.

C

Open and highlight the right passage

Ask for a known section or describe a topic. MoteLona opens an approved page, scrolls to the relevant passage and briefly highlights matching words in yellow.

02 / CAPABILITIES

Main functions

01

Local FAQ before hosted AI

Greetings, supported product questions, glossary definitions and evidence-backed Portfolio facts are handled locally. A hosted model is reserved for questions that need synthesis, which reduces free-API calls and avoids provider latency for common requests.

02

Portfolio and project retrieval

The backend combines current page context, public MongoDB records and passages from approved project files. Intent rules, TF-IDF, cosine similarity and term overlap rank relevant evidence; the system does not use neural embeddings.

03

Explain selected text

Select a word, sentence or paragraph and choose an explanation level. Known glossary terms are explained locally; other passages use relevant page context and a configured model when available. Web sources are added only when requested.

04

Page and passage navigation

Understands explicit requests such as “take me to the paragraph about MongoDB schema”, opens an approved page or section, scrolls to the relevant passage and briefly highlights the matching phrase in yellow. Destinations remain allow-listed.

05

Optional history and memory

Chat history and long-term memory are separate controls. Saving is off by default and requires the visitor to enable the relevant option; memory is only used with explicit consent.

06

MongoDB-backed portfolio data

When MongoDB is configured, the backend can read published profile, skill, education and project records, and persist consented chat history or memories.

07

Bounded provider calls and optional web

When generation is needed, Gemini, Groq and OpenRouter are tried in order, with each configured provider attempted once. The whole model chain is capped at 12 seconds and each attempt at 7 seconds. Web research runs only when requested; provider quotas, model access and response quality vary by account.

Privacy, fallback and free-tier limits

Local answers stay on the backend. When hosted generation is needed, the selected provider receives the question and relevant evidence; a timeout or service error may pass the request to the next configured provider within the 12-second budget. Safety refusals stop the chain. Web search sends a public query only when enabled. Provider terms and free quotas vary, so avoid sending passwords, API keys or sensitive personal details.

04 / KNOWLEDGE NOTES

The NLP concepts behind the assistant

These are useful building blocks to understand before moving from keyword-based search to modern semantic retrieval. The current code uses text normalization, token features, TF-IDF, cosine similarity and lexical overlap — not a neural embedding model.

⌕

6 concepts in this guide

No matching concept. Try another keyword.

01

NLP — Natural Language Processing

A field that helps computers work with human language: cleaning text, identifying patterns, classifying intent and retrieving relevant information.

Think: turn a sentence into data that software can process.
02

Tokenization

Breaking a sentence into smaller units such as words or subwords. MoteLona normalizes Vietnamese text, removes punctuation and creates selected two-word phrases.

Example: “kỹ năng Java” → “ky”, “nang”, “java”, “ky_nang”.
03

TF-IDF

A weighting method: a term becomes more useful when it appears often in one passage but is less common across the whole collection.

TF-IDF(t,d) = TF(t,d) × IDF(t)
04

Cosine similarity

Compares two text vectors by their direction. A larger value means the vectors point in a more similar direction; it is a relevance signal, not proof that an answer is correct.

cos(A,B) = (A · B) / (‖A‖ × ‖B‖)
05

Generative AI

A language model interprets a natural message and writes a new response using the supplied page context, Portfolio evidence and its general knowledge.

MoteLona uses the configured provider chain; the model does not learn from chat history.
06

Embeddings & semantic search

Embeddings map text into dense numerical vectors so that related meanings can be close even when they use different words. This is a possible future upgrade, not a feature of the current engine.

Do not describe the current TF-IDF engine as an embedding model.

Important distinction

Retrieval finds relevant information; generation turns that information into a response. A retrieval score alone cannot guarantee factual accuracy. Keep the source passage, test difficult questions and return an honest “not found” response when evidence is weak.

06 / ENGINEERING QUALITY

What makes an assistant dependable?

A useful assistant is not judged only by whether it replies. It should retrieve the right source, handle errors clearly, protect user data and behave predictably when it cannot answer.

✓

Controlled actions

Navigation is restricted to known destinations instead of executing arbitrary page instructions. This reduces accidental or unexpected actions.

◉

Consent-first storage

Chat history and long-term memory are separate settings. They are off by default in the interface and should remain transparent to visitors.

⌁

Useful error handling

If the backend, database or all providers are unavailable, the interface should say what happened and suggest a local answer or a retry. Weak evidence should produce an honest not-found response.

12s

Bounded model latency

Provider calls share a 12-second total budget; each provider gets at most 7 seconds and one attempt. This bounds model waiting time, while local retrieval and requested web research have their own processing time.

07 / SCOPE & LIMITATIONS

What this version can — and cannot — do

Available in this design

  • Common product and Portfolio questions use supported local answers first; synthesis goes to configured model providers only when needed, within a shared 12-second budget.
  • Portfolio Q&A, selected-text explanations, optional public web research and allow-listed navigation with passage highlighting.
  • Portfolio answers follow the published MongoDB records and current website content; the cards above show the latest public record counts.

Current limitations

  • Generated answers can still be wrong; verify important details against source pages and the original Portfolio records.
  • It does not train itself or learn online; new knowledge must be added and tested by the developer.
  • Each model provider depends on account permissions, model availability and changing usage limits.
  • Local answers only reflect available records and glossary entries; model answers may include general knowledge. Web sources are used only when requested and available.
  • This workspace's backend can connect to MongoDB; a public release still needs its own HTTPS backend URL, database access, exact CORS origins and deployment checks.
QUICK ANSWERS

Questions visitors often ask

Is MoteLona a general-purpose chatbot?

No. It is a bilingual assistant for this Portfolio. It answers questions about the public profile, education, skills, activity, projects and this website, explains selected text, and can search public sources when you turn that option on. Its local retrieval uses text matching rather than a neural language model.

Does web search use an API key?

Generative answers use any configured provider key: GEMINI_API_KEY, GROQ_API_KEY or OPENROUTER_API_KEY. Keep keys on the server, never in website JavaScript. Public web search has no model key but may be rate-limited. Free quotas and available models can change.

Do common questions use a free model API?

Supported FAQs, greetings, glossary definitions and Portfolio facts with enough local evidence are answered before hosted generation, so they do not call Gemini, Groq or OpenRouter. Questions that need synthesis may call a configured provider.

How long can a model request take?

All configured model providers share a maximum 12-second budget. Each provider is tried once for at most 7 seconds; any remaining time is used for the next configured provider. This limit applies to model calls, not local file retrieval or optional public web research.

What information is in the Portfolio database now?

The public database includes a profile, education and learning activity records, skills, and published projects. The six cards above show the live record counts, examples and active curated-knowledge count when the Portfolio API is reachable; the page shows the 24 November 2026 snapshot if it is offline.

Why can the assistant look available but not answer on a public website?

The interface is static HTML, CSS and JavaScript; chat needs the Java backend. Configure at least one provider key on that server for hosted generation; without keys, local Portfolio retrieval still works. Public deployment must configure an HTTPS backend URL, allowed CORS origins and database access.

Does MoteLona learn automatically from every conversation?

No. Optional history or memory is storage, not model training. The model does not train on these chats. Portfolio answers change when the published page or database records are updated.

What should be improved before adding a larger AI model?

First keep Portfolio records complete, review and add curated knowledge when it provides value, and measure local answer and retrieval quality on representative questions. Then evaluate embeddings or a retrieval-augmented generation design only if measured gaps justify them.
