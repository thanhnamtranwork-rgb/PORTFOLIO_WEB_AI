01 / OVERVIEW

What does MoteLona do?

MoteLona is not intended to be a general-purpose chatbot. It focuses on the information and interactions available on this portfolio, grounding its responses in page context, published portfolio records and a curated glossary.

A

Find information

Ask about the profile, education, skills and projects using content actually supplied by the website and database.

B

Understand terms

Select text or ask about a technical phrase to receive a definition from the integrated glossary and available context.

C

Open and highlight the right passage

Ask for a known section or describe a topic. MoteLona opens an approved page, scrolls to the relevant passage and briefly highlights matching words in yellow.

02 / CAPABILITIES

Main functions

01

Portfolio Q&A

Recognizes question groups such as profile, education, skills, projects, experience, contact and CV, then retrieves matching information from the supplied page context and Portfolio data.

02

Website text search

Searches the text available from the current page context. TF-IDF and term overlap help rank passages that best match the query.

03

Explain selected terms

Visitors can select a technical term and request a basic explanation. The glossary covers concepts such as NLP, tokenization, TF-IDF and cosine similarity.

04

Page and passage navigation

Understands explicit requests such as “take me to the paragraph about MySQL schema”, opens an approved page or section, scrolls to the relevant passage and briefly highlights the matching phrase in yellow. Destinations remain allow-listed.

05

Optional history and memory

Chat history and long-term memory are separate controls. Saving is off by default and requires the visitor to enable the relevant option; memory is only used with explicit consent.

06

MySQL-backed portfolio data

When MySQL is configured, the backend can read published profile, skill, education and project records, and persist consented chat history or memories.

07

Opt-in web search, no AI API

Web search mode or an explicit “Search the web for…” request sends the query to DuckDuckGo's public HTML results page. MoteLona shows result titles, snippets and source links; no AI API key or search API key is required. The server needs outbound HTTPS access.

03 / JAVA ARCHITECTURE

How the system processes a question

The main pipeline runs in the Java backend. The browser sends the question and bounded page context; Java classifies intent, retrieves relevant facts and chooses only registered actions. If the visitor explicitly requests a web search, a separate retrieval branch fetches public DuckDuckGo HTML results and returns source links.

IntentClassifier.java

KnowledgeRetrievalService.java

Ranks candidate knowledge passages using TF-IDF, cosine similarity and lexical overlap.

LocalAiEngine.java

Builds a response from the recognized intent, retrieved facts and predefined response patterns.

Web-search privacy and limits

The Java server sends a query to DuckDuckGo only after the visitor asks for a web search or turns on Web search. The query is not sent to an AI model. Search snippets can be incomplete, outdated or blocked by the provider, so open the source page before relying on a result. Search history is stored in MySQL only when chat-history storage is enabled separately.

04 / KNOWLEDGE NOTES

The NLP concepts behind the assistant

These are useful building blocks to understand before moving from keyword-based search to modern semantic retrieval. The current code uses text normalization, token features, TF-IDF, cosine similarity and lexical overlap — not a neural embedding model.

⌕

6 concepts in this guide

No matching concept. Try another keyword.

01

NLP — Natural Language Processing

A field that helps computers work with human language: cleaning text, identifying patterns, classifying intent and retrieving relevant information.

Think: turn a sentence into data that software can process.
02

Tokenization

Breaking a sentence into smaller units such as words or subwords. MoteLona normalizes Vietnamese text, removes punctuation and creates selected two-word phrases.

Example: “kỹ năng Java” → “ky”, “nang”, “java”, “ky_nang”.
03

TF-IDF

A weighting method: a term becomes more useful when it appears often in one passage but is less common across the whole collection.

TF-IDF(t,d) = TF(t,d) × IDF(t)
04

Cosine similarity

Compares two text vectors by their direction. A larger value means the vectors point in a more similar direction; it is a relevance signal, not proof that an answer is correct.

cos(A,B) = (A · B) / (‖A‖ × ‖B‖)
05

Intent classification

Identifies what the visitor is trying to do — for example, ask about skills, find a project or request a section navigation action.

The current implementation combines keyword rules and example matching.
06

Embeddings & semantic search

Embeddings map text into dense numerical vectors so that related meanings can be close even when they use different words. This is a possible future upgrade, not a feature of the current engine.

Do not describe the current TF-IDF engine as an embedding model.

Imagine a visitor asks: “Where can I see Java skills?” The system does not understand the sentence like a person. It transforms and scores available text, then chooses the strongest matching passage.

Important distinction

Retrieval finds relevant information; generation turns that information into a response. A retrieval score alone cannot guarantee factual accuracy. Keep the source passage, test difficult questions and return an honest “not found” response when evidence is weak.

06 / ENGINEERING QUALITY

What makes an assistant dependable?

A useful assistant is not judged only by whether it replies. It should retrieve the right source, handle errors clearly, protect user data and behave predictably when it cannot answer.

✓

Controlled actions

Navigation is restricted to known destinations instead of executing arbitrary page instructions. This reduces accidental or unexpected actions.

◉

Consent-first storage

Chat history and long-term memory are separate settings. They are off by default in the interface and should remain transparent to visitors.

⌁

Useful error handling

A missing backend, unavailable database or unmatched question should result in a clear status — not a fabricated answer or a silent failure.

⌕

Tests in the codebase

The project includes JUnit test classes for intent classification, local responses, action routing, glossary, local search, memory, rate limiting, portfolio data and the MySQL schema contract. Their presence does not mean deployment checks have all passed.

07 / SCOPE & LIMITATIONS

What this version can — and cannot — do

Available in this design

  • Local Java NLP and retrieval; no external AI API key is required.
  • Portfolio Q&A, glossary explanations and allow-listed navigation.
  • Knowledge can be expanded by updating database records, glossary entries and intent examples.

Current limitations

  • It is not a general-purpose LLM like ChatGPT or Gemini and does not generate open-ended knowledge at that level.
  • It does not train itself or learn online; new knowledge must be added and tested by the developer.
  • Web search uses DuckDuckGo's public HTML results page without an API key, but requires outbound Internet access and may stop working if the search page changes or blocks automated requests.
  • Search snippets are not independently verified or synthesized by a general-purpose language model. Open the source pages before relying on current, legal, medical or financial information.
  • Production still needs a live MySQL instance, a public HTTPS backend, exact CORS origins and deployment-specific smoke checks.
QUICK ANSWERS

Questions visitors often ask

Is MoteLona the same as ChatGPT?

No. This build uses a focused Java NLP pipeline with intent rules and TF-IDF retrieval. It is not a general-purpose generative language model. Its advantage is a bounded, explainable scope over this portfolio.

Does web search use an API key?

No AI or search API key is required. When a visitor explicitly asks for web search, the Java server sends the query to DuckDuckGo's public HTML search page and displays result snippets with source links. The server needs Internet access, and DuckDuckGo may change or restrict this page.

Why can the assistant look available but not answer on a public website?

The interface is static HTML, CSS and JavaScript, but actual chat requests need the Java backend. A public deployment must configure an HTTPS backend URL, CORS origins, database access and server environment variables.

Does MoteLona learn automatically from every conversation?

No. Optional history or memory is storage, not model training. The current knowledge base changes only when the developer updates approved data, glossary entries or intent examples and then tests the results.

What should be improved before adding a larger AI model?

First verify the Java and MySQL pipeline, create representative test questions, measure retrieval quality and define privacy rules. Then evaluate embeddings or a retrieval-augmented generation design against measurable gaps.

The best next step is not to add every AI technology at once. Improve the quality of the current pipeline, measure it, and then introduce more advanced components where they solve a real limitation.
